**Extended verifier — 13/14 PASS** (`acceptance-report-extended.txt`). Ours, not the organizers': the published
checker declares `TIERS = ["T1","T2","T3","T4"]` but ships only the seven T1/T2 checks above, so T3 has no
official receipt. This script fills that gap and is committed with its output.

The one failure is `voting ballot loads` — "ballot page missing expected content". The ballot is client-rendered,
so a static HTML fetch cannot see it. The same wall the official checker hit with the gallery, which was solved
there with a title-bearing plain route; the vote page has no equivalent. The ballot's *data* is proven by the
gallery, counts and influence checks. **T3 is therefore not claimed as verified**: the verifier itself reports
`verified nothing` while any check fails, which is the honest outcome.

> **Reproducing the receipt:** the root `.env` (gitignored) must define `POSTGRES_PASSWORD` and
> `BETTER_AUTH_SECRET`, and `apps/server/.env` must share that same secret. If the host mints cookies with a
> different secret than the container verifies, every authenticated check 401s — and because a 401 is also a
> deny, the isolation checks still report PASS. Refresh with `bun run seed:config` after any secret change.
> The stack must be running: `docker compose up -d`.

## Summary

- **T1 and T2 are complete**, each row with a real code path, and T1/T2 carry a committed machine receipt (7/7).
- **T3 is implemented and 13/14 verified, but not claimable yet.** Voting, quadratic influence, comments,
  randomised ballots and the results-visibility gate all have machine receipts. Two things stand between it and a
  claim: the ballot is client-rendered so one check cannot see it, and email-gated voting has no mailer, so the
  code is returned in the response outside production rather than delivered.
- **T4 is essentially absent.** No webhooks, certificates, signed records or embeddable widget; no bulk import;
  the oRPC surface is not a documented REST API.
- **Do not claim T3 yet.** 13 of 14 checks pass, but the verifier reports `verified nothing` while any check
  fails, and a claim the checker cannot confirm scores as the lower tier anyway.
- **Standing caveat:** two `biome-ignore` suppressions on TanStack Query's `isLoading` were confirmed `boolean`
  by `tsc`; Biome approximates the overloaded `useQuery` return as a literal `false`.

> Priority: email-gated enum fix → randomised ballot wiring → run `verify-extended.py` and commit its output →
> only then claim T3. T4 last, if at all: the spec states a clean T2 outscores a broken T4, and T4 is where a
> half-built result does the most damage.
